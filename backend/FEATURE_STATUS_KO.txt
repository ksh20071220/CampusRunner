CampusRunner 담당 기능 구현 점검표
기준: 2026-10-26 / C11 HTTP 백엔드 / 스키마 버전 2

사용자 담당 범위: 회원/소속 대학 등록, 대학별 합산, 1인당 평균 거리,
대학별 순위, 비정상 기록 탐지. 아래 완료는 백엔드 API 기준이다.

1. 회원/대학 기능

  회원가입: 완료. 닉네임/비밀번호/대학 ID 검증, 중복 방지, 해시 저장, 세션 발급.
  로그인: 완료. 비밀번호 검증, 만료 세션 정리, 계정별 최근 8개 세션, 인증 시도 제한.
  현재 기기 로그아웃: 완료. 사용한 토큰만 폐기.
  전체 기기 로그아웃: 이번에 추가. POST /api/auth/logout-all {} -> 204.
  내 프로필 조회/변경: 완료. 닉네임 변경, 러닝 전 대학 변경과 이전 소속 인증 취소.
    기록이 생긴 뒤 대학 변경은 점수 이관 방지를 위해 409로 제한한다.
  비밀번호 변경: 이번에 추가. PATCH /api/me/password {current_password,new_password}.
    현재 비밀번호 재확인, 새로운 salt/해시, 모든 기존 세션 폐기, 교체 토큰 발급.
  회원탈퇴: 이번에 추가. DELETE /api/me {password,confirmation:"DELETE"} -> 204.
    본인 세션/비밀번호를 재확인하고 회원/사진/신청/이력/GPS/러닝/세션을 원자적으로 삭제.
    다른 회원/대학은 보존하고 탈퇴자의 거리·참가 인원·평균·순위를 즉시 다시 계산한다.
    잘못된 비밀번호/확인 문구/타인 ID 주입은 거부한다. 실패 시 모두 롤백한다.
    같은 닉네임 재가입은 새 회원이며 이전 인증/점수/토큰을 물려받지 않는다.
  한국 대학 선택 목록: 완료. 내장 385개, 이름/이전 이름/지역/종류 검색, 관리자 추가 등록.
  소속 대학 수동 인증: 완료. 학생증/합격증 JPEG·PNG 제출, 동의/크기/치수 제한,
    본인 신청 조회/취소, 관리자 목록/사진/승인/반려/철회/이력, 7일 미검토 만료.

2. 합산/평균/순위/비정상 판정

  대학별 거리 합산: 완료. 같은 서버의 SQLite DB에서 소속 승인 회원의 정상·양수 거리 합산.
  참가자 1인당 평균: 완료. 기간 안 정상·양수 기록이 있는 인증 회원을 DISTINCT로 센다.
    대학 전체 재학생 수 또는 가입자 전체 수로 나누지 않는다. 활동 0명은 0m.
  기간별 순위: 완료. 시작 시각 기준 [from,to), 평균 거리 내림차순, 공동 순위 1/1/3,
    모든 대학의 순위를 계산한 뒤 페이지 처리. 특정 대학 조회도 같은 전체 순위를 쓴다.
  비정상 탐지: 완료. 순간 구간/30초 평균/전체 평균 속도, GPS 단절, 장시간 기록 판정.
    서버가 좌표에서 재계산하고 의심 기록은 개인 기록에 남기되 대학 점수에서 제외한다.
    중복 재전송/같은 좌표 재등록/정상 러닝 시간 겹침/잘못된 좌표/미래 시각도 검사한다.
    느린 자전거·위치 조작·모든 GPS 오차를 확정적으로 구분하는 기능은 아니다.

3. 이번 점검에서 함께 보완한 오류

  로그인/비밀번호 변경/탈퇴의 자격 증명을 쓰기 잠금 안에서 다시 확인한다.
  쓰기 잠금 대기 중 세션이 취소되면 프로필/러닝/사진/취소 요청을 401로 거부한다.
  비밀번호 변경 중 세션 발급 실패, 탈퇴 마지막 삭제 실패를 강제로 주입해 전체 롤백을 검사한다.
  CivetWeb 기본 CORS preflight 자동 응답을 끄고 앱의 정확한 Origin 정책을 적용한다.
    실제 Access-Control-Request-Method: DELETE 요청과 허용하지 않은 Origin을 테스트한다.
  본인 신청/이력 조회 및 탈퇴 삭제용 member_id 인덱스를 추가했다. 스키마 버전은 유지한다.

4. 팀원이 연결할 것과 외부 환경 작업

  examples/api-client.js가 회원/대학/러닝/인증 API 호출을 제공한다.
  회원가입/로그인/계정 설정/탈퇴 화면은 프런트엔드에서 연결해야 한다.
    탈퇴 버튼에는 영구 삭제·대학 점수 감소를 안내하고 사용자의 명시적인 확인을 받는다.
    성공한 탈퇴/전체 로그아웃 뒤 token을 비우고, 비밀번호 변경 뒤 교체 token을 저장한다.
  현재 닉네임이 로그인 식별자다. 닉네임 변경 뒤 로그인에는 새 닉네임을 사용한다.
  이메일/전화번호 기반 비밀번호 분실 복구: 미구현. 현재 회원 모델에 이메일이 없으며,
    실제 복구 수단/소유 확인/발송 채널을 정한 후 구현해야 한다. 비밀번호 변경과 구별한다.
  독립된 운영자 계정/권한 분리: 미구현. 현재 관리자 검토는 공동 비밀 토큰을 사용한다.
  실제 도메인 HTTPS/프록시/IP 제한/OS 파일 권한/백업 보관은 배포 환경에서 설정해야 한다.
  탈퇴는 운영 DB 기준이다. 기존 백업 복원 시 회원이 되살아날 수 있으므로 과거 사본도 관리한다.
  Linux/Docker 실행과 실제 휴대폰 GPS 수집은 이 PC에서 검증하지 않았다.

5. 검증과 변경 위치

  실제 프로젝트 경로에서 C 단위·CLI 5개·HTTP 46개·백업 7개·관리자 화면 11개·회원 클라이언트 5개 통과.
  CMake/CTest 6개 묶음도 통과했으며 직접 작성한 C 코드의 MSVC 정적 분석에서 경고가 없었다.
  탈퇴 후 집계 재계산, 다른 회원 보존, 모든 세션 무효화, 사진/감사 기록 삭제,
  재가입 분리, 비밀번호 오류/입력 제한, 동시 변경, DB 오류 롤백, CORS를 검증한다.
  src/auth_api.c: 회원 수명주기/자격 증명 재확인/세션 처리.
  src/api.c: DELETE 본문/라우팅/사전 권한/CORS 응답.
  src/server_main.c: 라이브러리 자동 preflight 응답 비활성화.
  src/runs_api.c, src/verification.c: 쓰기 시 세션 재확인.
  src/database.c: 회원별 검토/이력 인덱스. 신규 스키마 마이그레이션은 필요 없다.
  tests/test_server.py, tests/test_api_client.cjs: 실제 HTTP/프런트 연결 회귀 검사.
  API.md/BACKEND_HANDOFF_KO.txt: 정확한 요청/응답/변수·함수 규칙.
