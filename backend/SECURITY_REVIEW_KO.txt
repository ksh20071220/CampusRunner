CampusRunner 코드·백엔드 보안 점검 기록
정리: 2026-10-26 / 구현·로컬 검증: 2026-10-22~2026-10-26
대상: feature/c-backend-university-challenges, 변경 전 98f1b74
인코딩: UTF-8 / 모든 경로는 저장소 루트 기준

1. 점검 범위

  직접 작성한 C 분석/CLI/HTTP 서버, 회원·세션·관리자 권한, SQLite 트랜잭션,
  대학 집계, 사진 인증/감사 이력, 브라우저 API/관리자 화면, 백업, 빌드/배포 설정을 검토했다.
  벤더 전체를 독립 감사한 것은 아니다. 공개 이슈와 현재 빌드 옵션/호출 경로를 대조했다.
  테스트는 임시 DB와 본인 PC의 localhost 서버에만 실행했다. 실사용 사진은 쓰지 않았다.

2. 재현한 오류와 수정

  A. 잘못된 JSON 숫자와 공백 수용
     변경 전 대학 등록에 id=03, id=4., 수직 탭 공백을 넣으면 201이었다.
     cJSON 호출 전에 strict_json_input()으로 숫자/문자열/이스케이프/UTF-8을 검사한다.
     변경 뒤 400이다. 유효한 지수 표기·한글·이모지는 계속 지원한다.
     최대 2MiB, 깊이 32, 어휘 토큰 180,000개로 파싱 작업량을 제한한다.
     GPS 20,000점이 정상 등록되는 경계 테스트도 추가했다.

  B. URL 디코딩된 NUL에 의한 숫자 접두사 수용
     변경 전 from=0%00junk, limit=1%00junk를 숫자 0/1로 처리해 200이었다.
     쿼리 값의 디코딩 결과를 길이 기준으로 검사해 NUL/제어 문자/잘못된 UTF-8을 거부한다.
     잘못된 % 시퀀스도 400이다. 한국어 검색은 그대로 동작한다.
     경로는 라이브러리 자동 디코딩을 끄고 % 자체를 거부해 인코딩에 따른 경로 별칭을 없앴다.

  C. 백업 정리 실패 시 사진을 담은 최종 파일 잔류
     변경 전 사진 제거 UPDATE에 실패를 주입하면 최종 백업 파일에 원본 사진이 남았다.
     현재는 보호된 임시 디렉터리에서 복사/사진 제거/세션 삭제/VACUUM/무결성 검사를 한다.
     모두 성공한 파일만 같은 파일시스템의 하드링크로 최종 이름에 공개한다.
     처리 예외와 공개 실패 때 임시 파일을 정리하며, 경합 중 생성된 다른 파일도 보존한다.
     하드링크 미지원 환경에서는 실패한다. 안전하지 않은 직접 복사로 대체하지 않는다.
     원본 DB의 사진/세션은 바꾸지 않는다. 백업에 회원/비밀번호 해시/GPS는 남는다.
     프로세스 강제 종료/OS 장애까지 임시 파일 정리를 보장하지는 않는다.

  D. 복원 시 폐기된 로그인 세션 부활 가능성
     백업 시점 뒤 로그아웃한 토큰이 이전 사본 복원으로 되살아날 수 있었다.
     새 백업에서는 sessions를 비운다. 복원 후 이전 토큰은 401이며 재로그인이 필요하다.
     이 변경 전에 만든 백업에는 적용되지 않는다.

3. 코드 점검으로 확인해 보완한 부분

  HTTP 헤더: 단일 값이어야 하는 Host/Content-Length/Authorization/Origin/Content-Type/
    X-Document-Type/X-Verification-Consent의 중복을 거부한다. 길이는 십진수 숫자만 허용한다.
    Transfer-Encoding은 지원하지 않는다. 잘못된 길이·중복 헤더는 raw socket 테스트로 400을 확인했다.
    이는 앱 경계의 검증이며 운영 프록시 전체의 요청 스머글링 방지를 인증한 결과는 아니다.
  인증 순서: 보호된 POST/PATCH는 본문을 읽거나 JSON 트리를 만들기 전에 인증한다.
    Content-Length만 보내고 본문을 보내지 않아도 즉시 401/403인지 검사했다.
    라우터에서도 세션을 다시 확인해 읽기 도중 폐기된 토큰을 계속 신뢰하지 않는다.
  DB 초기화: 버전 조회를 쓰기 잠금 뒤로 이동하고 스키마 변경 전체를 한 트랜잭션에 묶었다.
    같은 빈 WAL DB에 두 서버를 동시에 시작해 둘 다 정상 시작/무결성/버전 2를 확인했다.
  설정: listen은 IPv4:1~65535 형식만 허용한다. 포트만 지정해 전체 인터페이스에
    뜻하지 않게 열리는 설정을 거부한다. Origin은 http(s) 호스트/선택적 포트 형식만 받는다.
    잘못된 설정에서 DB를 만들기 전에 종료하는 테스트를 추가했다.
  파일 권한: POSIX 서버 시작 때 umask 077을 적용해 새 DB/WAL/저널의 접근 범위를 제한한다.
    기존 파일 chmod와 Windows ACL 변경은 하지 않는다. Linux 실행은 이번 PC에서 검증하지 못했다.
  컨테이너: .dockerignore에 .env, DB/SQLite/WAL, 토큰, PEM/키, Git 메타데이터 제외를 추가했다.
    Docker 빌드 컨텍스트/빌더 캐시에 로컬 비밀 파일이 들어가지 않도록 하는 설정이다.
  요청 계약: 취소·로그아웃은 빈 객체만 받고 추가 필드를 거부한다.

4. 함께 재확인한 기존 동작

  사용자별 salt/PBKDF2-HMAC-SHA256 600,000회, 난수 세션과 DB 해시 저장,
  7일 만료/로그아웃/회원당 최근 8개 세션, 원격 IP별 가입·로그인 제한.
  Prepared statement, 외래 키·유일성 제약, 동시 중복 제출/기간 겹침 방지,
  실패 시 롤백과 검토/만료/대학 변경 이력의 원자성.
  다른 회원의 러닝/사진/신청 상세 접근 차단, 관리자 경로 권한 검사,
  수동 승인된 소속의 정상 기록만 대학 합산, 전체/특정 대학의 같은 공동 순위.
  사진 크기/형식/치수 제한, 비공개 BLOB 저장, 처리 뒤 활성 이미지 제거,
  no-store/nosniff/CSP 이미지 응답, DOM textContent 렌더링과 늦은 응답 폐기.
  사진 검사는 구조 검사이며 이미지 전체 디코딩·악성 파일 검사·문서 진위 판정은 아니다.

7. 운영 환경에서 남는 일

  실제 도메인의 HTTPS 프록시와 프런트엔드 Origin을 설정해야 한다. API 자체는 HTTP다.
  공개 서비스에는 프록시의 실제 IP 기준 요청 제한이 필요하다. X-Forwarded-For를
  무조건 신뢰하도록 바꾸지 않는다. 현재 앱 제한은 직접 연결한 remote_addr 기준이다.
  공동 관리자 토큰의 reviewer 문자열은 인증된 운영자 계정 신원이 아니다.
  운영자별 로그인/권한 분리·비밀번호 복구는 별도 기능이다.
  DB·토큰·백업은 접근 제한된 운영 디렉터리에 보관하고 동기화/외부 스냅샷도 관리한다.
  SQLite 파일 자체를 암호화하지는 않는다. 저장 장치 암호화와 OS 계정 권한을 적용해야 한다.
  GPS 조작과 느린 자전거를 완벽히 판별하지 못한다. 실제 GPS 표본으로 정책을 검증해야 한다.
  Linux/Docker/실제 휴대폰·운영 HTTPS 구성은 이번 PC에서 실행 검증하지 못했다.
  원격 CI 결과도 이 로컬 검증과 별개다. main 머지·원격 푸시·운영 배포는 수행하지 않는다.
