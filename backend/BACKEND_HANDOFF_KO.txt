[0] 처음 합류한 작업자가 알아둘 것

이 프로젝트의 공용 백엔드는 backend/build/campus_server.exe이다.
휴대폰마다 별도 DB를 만드는 방식이 아니라 모든 클라이언트가 같은 HTTP 서버에 요청한다.
회원 ID, 소속 대학, 거리, 순위는 서버가 결정한다. 브라우저가 계산한 점수를 신뢰하지 않는다.
학생증/합격증은 운영진이 직접 확인한다. 자동 OCR이나 AI 문서 승인은 구현하지 않았다.

현재 작업 브랜치: feature/c-backend-university-challenges
작업을 이어갈 때 git status와 현재 브랜치를 먼저 확인한다.
main 직접 수정/머지, 원격 푸시, 운영 배포는 이번 작업에서 수행하지 않았다.

  2. backend/API.md: 회원/러닝/순위 HTTP 규격

[1] 전체 구조와 실제 호출 흐름

  모바일 웹 -> HTTP JSON/사진 -> CivetWeb -> cr_api_handler()
    -> 헤더/Origin/쿼리 검사 -> 요청별 SQLite 연결 -> 쓰기 권한 검사
    -> JSON 검사 -> 만료 정리
    -> auth / runs / verification 라우터
    -> DB 트랜잭션 및 GPS 분석 -> cr_reply() -> HTTP 응답

사용 라이브러리:
  HTTP: CivetWeb / JSON: cJSON / DB: SQLite
  Windows 암호화: BCrypt / Linux 암호화: OpenSSL Crypto
  vendor/의 원본과 라이선스는 유지한다. 일반 기능은 src/에서 수정한다.

중요한 구분:
  campus_server = 실서비스 연동용 HTTP + SQLite 서버
  campus_runner = 초기 CLI + TSV 파일 도구
  CLI의 CrStore/TSV와 서버 SQLite는 별도 저장소다. 자동 동기화하지 않는다.
  한국 대학 385개 목록은 서버에 시드한다. CLI 대학 상한 128과 혼동하지 않는다.

[3] 이름 규칙과 기존 약어를 읽는 법

  cr_*                 공용 C 함수 접두사. 예: cr_analyze_run(), cr_db_open().
  CrPoint, CrRun       구조체/타입은 Cr + PascalCase.
  CR_*                상수, 상태값, 비트 플래그.
  member_id           내부 회원 식별자. 요청 본문으로 타인 ID를 받지 않는다.
  university_id       내부 대학 식별자. 학교명이나 외부 공공데이터 ID와 다르다.
  request_id          대학 인증 신청 식별자. 러닝 ID와 섞지 않는다.
  client_key / key    클라이언트가 러닝 한 번에 발급하는 재전송 식별자.
  fingerprint/digest  정규화한 GPS JSON의 SHA-256 32바이트. 중복 활동 검사에 사용한다.
  token               응답으로 주는 64글자 소문자 16진수 회원 토큰.
  token_hash          토큰 문자열의 SHA-256 32바이트. DB에는 이것만 저장한다.
  salt/password_hash  비밀번호용 난수 16바이트 / KDF 결과 32바이트.
  flags               GPS 이상 이유를 OR로 합친 비트 마스크. 단일 상태 enum이 아니다.
  response/status     문맥 확인: response는 보통 HTTP 코드, verification status는 문자열.
  step/result         sqlite3_step() 결과. SQLITE_ROW와 SQLITE_DONE은 의미가 다르다.
  stmt/statement      SQLite prepared statement 핸들. 반드시 finalize한다.
  r/request           보통 CrRequest*. HTTP 요청 한 건의 문맥이다.
  s/store             campus_runner.c에서는 CrStore*, verification.c에서는 SQL stmt일 수 있다.
  p/point/item        문맥에 따라 정책, GPS 좌표, JSON 항목. 선언 타입부터 확인한다.
  i/left/cumulative   좌표 인덱스 / 30초 경계 왼쪽 인덱스 / 누적 거리 배열.
  cutoff              만료 정리 시작 때 고정한 현재 UTC 초. 이력/삭제 SQL에 같은 값을 쓴다.
  limit/offset        페이지 크기 / 건너뛸 행 수. 배열 인덱스가 대학 순위는 아니다.

새로 추가하는 코드에서는 request_id, university_id, statement처럼 의미를 드러낸다.
기존 JSON 필드명은 다른 팀 코드와의 계약이므로 변수 정리만을 위해 바꾸지 않는다.

[4] 핵심 구조체와 메모리 소유권

CrServer (api.h)
  db_path, admin_token, allowed_origin: 서버 설정 문자열. 실행 중 요청이 공유한다.
CrRequest (api.h)
  conn: CivetWeb 연결, info: 요청 메타데이터, server: 위 설정.
  db: 요청별 SQLite 연결, body: 파싱한 JSON, member_id: 인증으로 확인한 회원.
  token_hash[32]: 인증된 회원 토큰의 해시. 관리자 토큰과 별개다.
CrPoint (campus_runner.h)
  latitude, longitude: 위도/경도 실수. timestamp: int64_t UTC 초.
CrPolicy
  max_segment_mps, max_window_mps, max_average_mps: 이상 속도 기준.
  window_seconds, max_gap_seconds, max_duration_seconds: 시간 기준.
CrRun
  key, member_id, university_id, started_at, ended_at: 활동의 식별/귀속/기간.
  distance_m, max_segment_mps, max_window_mps, average_mps, flags: 분석 결과.
CrRanking
  university_id, rank, participants, runs, distance_m, average_distance_m.
CrStore
  universities/members/runs 고정 배열과 각 count. CLI 전용이며 큰 구조체다.

소유권 약속:
  cr_reply(request, code, json)는 전달된 JSON을 출력한 뒤 삭제한다. 호출자가 다시 삭제하지 않는다.
  r.body와 r.db는 cr_api_handler()가 마지막에 정리한다. 라우터가 임의로 닫지 않는다.
  cJSON_AddItemToArray/Object()에 넘긴 자식은 부모 소유다.
  cJSON_PrintUnformatted() 결과와 malloc/calloc 메모리는 사용 후 free한다.
  sqlite3_column_text/blob() 주소는 해당 statement가 소유한다.
  step/reset/finalize 후 그 주소를 사용하지 않는다. 필요하면 먼저 복사한다.
  SQLITE_TRANSIENT bind는 SQLite가 복사하고, SQLITE_STATIC은 원본 수명이 충분해야 한다.
  실패 경로에서도 finalize/free/ROLLBACK이 빠지지 않도록 한다.

[5] 단위, 입력 제한, 공통 규칙

  시간: UTC Unix 초(int64_t). JS Date.now() 값은 /1000 후 정수로 바꾼다.
  기간: [from,to), 시작 포함/끝 제외. from/to 필수, 0 <= from < to <= 4102444800.
  거리: API/분석은 m, DB runs.distance_mm는 러닝별 반올림한 mm 정수.
  속도: m/s. km/h를 표시하려면 *3.6. pace_seconds_per_km는 초/km.
  이름: UTF-8 95바이트까지. CR_NAME_SIZE=96은 마지막 NUL 포함 용량이다.
  러닝 key: UTF-8 63바이트까지. CR_KEY_SIZE=64도 NUL 포함이다.
  비밀번호: UTF-8 8~128바이트. 이름과 함께 제어 문자/앞뒤 ASCII 공백을 거부한다.
  한글은 보통 UTF-8 3바이트이므로 글자 수와 바이트 수를 혼동하지 않는다.
  Unicode 정규화는 하지 않으며 닉네임/학교명은 대소문자를 구분한다.
  일반 JSON: 최대 2MiB, GPS: 2~20,000개, timestamp는 엄격히 증가해야 한다.
  분석 라이브러리 CR_MAX_POINTS=100000과 HTTP 상한 20000은 다르다.
  사진: JPEG/PNG, 최대 5MiB, 각 변 12000px 이하, 총 4000만 픽셀 이하.
  JSON 중복 키/추가 GPS 필드/잘못된 숫자/허용되지 않은 Origin은 거부한다.

[6] 회원/소속 등록과 인증

  회원 가입 -> university_id 존재 확인 -> 회원 저장 -> 세션 발급.
  회원 ID는 서버가 발급한다. 비밀번호는 PBKDF2-HMAC-SHA256 600000회로 저장한다.
  회원 토큰은 7일 유효하며 계정당 최근 8개 세션을 유지한다.
  로그아웃은 현재 토큰만 폐기한다. 비밀번호 복구 이메일은 구현하지 않았다.
  가입/로그인은 원격 IP 기준 60초 30회 제한을 공유한다.
  X-Forwarded-For는 신뢰하지 않는다. 프록시 뒤에서는 프록시 IP에 제한이 합산된다.
  공개 서비스의 프록시 IP/인증 제한 구성은 README의 배포 안내를 확인한다.

  university_verified_at != NULL이면 대학 인증 완료다.
  verification_status는 미제출/not_submitted, pending, approved, rejected,
  cancelled, expired, revoked 중 하나다. 개인 러닝 저장은 인증 전에도 허용한다.
  승인 후에는 해당 회원의 과거 정상 기록도 조회 기간 규칙에 따라 대학 점수에 반영한다.
  러닝이 하나라도 생기면 대학 변경은 차단한다. 같은 대학 값 재전송은 허용한다.
  실제 대학 변경 때 이전 pending/approved 신청을 cancelled로 바꾸고 사진/인증을 해제한다.
  닉네임은 기록이 있어도 변경할 수 있다. 대학 등록/추가는 관리자 API를 사용한다.

[7] GPS 제출, 거리 계산, 비정상 탐지

  1. 토큰으로 member_id 확인. 요청은 {key,points}만 받는다.
  2. timestamp/위도/경도/좌표 수 검사. 종료가 서버 현재+300초를 넘으면 400.
  3. cr_analyze_run()에서 Haversine 거리와 속도를 계산한다.
  4. 필드 순서와 숫자 표현을 정규화한 GPS JSON을 만들고 SHA-256 해시를 구한다.
  5. BEGIN IMMEDIATE 후 중복/시간 중첩 검사, 현재 회원 대학을 읽어 INSERT.
  6. 정상/의심 결과를 저장하고 응답. 소속/점수는 클라이언트가 지정하지 않는다.

  거리: 지구 반지름 6371000m의 Haversine 공식, 각 연속 구간 거리의 합.
  평균 속도: 총 거리 / (마지막 시각 - 시작 시각).
  30초 속도: 누적 거리 배열과 left 인덱스로 O(n) 슬라이딩 윈도 계산.
  30초 경계가 표본 사이면 그 구간의 일정 속도를 가정해 보간한다.
  0m 정상 기록의 페이스는 null이다. 프런트에서 0으로 나누지 않는다.

  비트/응답 이유/기준 (초과일 때만 이상):
    1  CR_FAST_SEGMENT  fast_segment  구간 속도 > 10m/s
    2  CR_FAST_WINDOW   fast_window   직전 30초 속도 > 6m/s
    4  CR_FAST_AVERAGE  fast_average  전체 평균 > 6m/s
    8  CR_GPS_GAP       gps_gap       표본 간격 > 120초
   16  CR_LONG_DURATION long_duration 전체 시간 > 21600초
  예: flags=5는 구간 속도+평균 속도 이상이다. flags==1 같은 단일 값 비교만 하지 않는다.

  입력 자체가 잘못되면 저장하지 않고 400.
  형식은 맞지만 의심이면 201, accepted=false로 저장하고 전체 활동을 대학 점수에서 제외.
  accepted=true와 counts_for_university=true는 다르다. 후자는 소속 승인도 필요하다.
  정책은 cr_default_policy()에서 바꾼다. 변경 시 policy_version/문서/테스트도 함께 검토한다.
  기존 기록은 자동 재판정하지 않는다. GPS만으로 모든 자전거/위치 조작을 구분하지 못한다.

재전송/공정성:
  같은 회원, 같은 key, 같은 GPS: 기존 결과 200. 최초 저장은 201.
  같은 key에 다른 GPS: 409 submission_key_conflict.
  다른 key에 같은 GPS: 409 duplicate_run.
  동일 회원의 정상 양수 거리 활동 시간이 겹침: 409 overlapping_run.
  인접한 종료/다음 시작 시각이 같은 것은 허용한다.
  네트워크가 끊겨도 저장됐을 수 있으므로 같은 key와 같은 points로 재시도한다.

[8] 대학별 합산/평균/전체 순위

  계산 위치: runs_api.c의 rankings(), SQLite CTE totals -> scored -> ranked.
  포함 조건: flags=0, distance_mm>0, from <= started_at < to,
             현재 회원 대학 = 기록 대학, 현재 university_verified_at이 NULL이 아님.
  총 거리 = 포함되는 모든 runs.distance_mm 합 / 1000.
  참가자 = 포함 기록을 가진 DISTINCT member_id 수.
  1인당 평균 거리 = 총 거리 / 참가자. 참가자 0이면 평균도 0.
  한 사람이 3번 뛰어도 분모는 1명이다. 미인증/미활동 회원은 분모에 넣지 않는다.
  활동 없는 대학도 LEFT JOIN으로 0점 행에 포함한다.
  평균 내림차순 공동 순위는 1,1,3이다. 동점 표시 순서는 대학 ID 오름차순이다.
  랭킹 계산 뒤 페이지를 자른다. 화면 반올림 값으로 다시 순위를 정하지 않는다.
  기간 귀속은 러닝 시작 시각 기준이다. 자정을 넘어도 거리를 기간별로 나누지 않는다.

  GET /api/rankings는 배열을 반환한다.
  GET /api/universities/{id}/stats는 같은 기간의 해당 대학 항목 한 개를 객체로 반환한다.
  university_id=0은 rankings() 내부에서 전체 조회를 뜻한다. 공개 경로의 0 ID는 허용하지 않는다.
  특정 대학 필터도 ranked CTE 뒤에 적용한다. 먼저 학교를 거르면 모든 학교가 1등이 된다.
  없는 대학은 404, 활동 없는 기존 대학은 0점 객체다.
  별도 합산 카운터를 저장하지 않아 중복 증가/누락 위험을 줄인다.

[9] 사진 제출, 수동 검토, 처리 이력

  업로드 본문은 파일 원본 bytes다. JSON/base64/multipart가 아니다.
  필수 헤더: Authorization, Content-Type, X-Document-Type, X-Verification-Consent: 1.
  문서 종류: student_card / admission_letter / enrollment_certificate / other.
  회원당 pending 1건, 최근 24시간 제출 최대 5건, 대기 기한 7일.
  서버는 이미지 시그니처/구조/크기를 검사한다. 문서 내용과 진위는 운영진이 확인한다.

  상태 전이:
    제출 -> pending -> approved 또는 rejected (관리자)
    pending -> cancelled (회원 취소/대학 변경)
    pending -> expired (7일 만료)
    approved -> revoked (관리자 철회) 또는 cancelled (대학 변경)
  처리/취소/만료 시 image=NULL. 사진 없는 원본 조회는 410 image_deleted.
  승인 시 회원 인증 시각을 설정하고, 철회/대학 변경 시 인증을 해제한다.
  다른 회원 사진/신청은 404, 일반 회원의 관리자 경로 접근은 403이다.

  verification_audit에는 action/reviewer/reason/created_at을 누적한다.
  승인 후 철회해도 이전 승인 이벤트를 덮어쓰지 않는다.
  GET /api/admin/university-verifications/{id}/audit는 관리자만 조회할 수 있다.
  자동 만료: expired / system / review_window_expired.
  대학 변경: cancelled / member / university_changed.
  회원 취소: cancelled / member / withdrawn_by_member.
  수동 승인/반려/철회: 입력한 담당자와 사유를 저장한다.
  reviewer는 공동 관리자 토큰 사용자가 적은 이름이며 별도 인증한 운영자 신원은 아니다.
  submitted_at은 제출 시각이다. 제출 자체를 audit 이벤트로 중복 생성하지 않는다.
  reviewed_at은 수동 처리 시각이며 자동 만료의 사건 시각은 audit.created_at에서 확인한다.
  이전 버전에서 누락된 자동 처리 이력은 추정해서 채우지 않는다.

  cr_db_expire_verifications()는 만료할 행이 없으면 읽기 검사만 한다.
  만료할 행이 있으면 BEGIN IMMEDIATE -> 이력 INSERT -> 상태/사진 UPDATE -> COMMIT.
  다른 요청이 먼저 만료시켜도 pending 조건을 다시 검사하므로 이력을 중복 생성하지 않는다.
  대학 변경/수동 처리도 상태 변경과 이력 저장이 한 트랜잭션이다.
  이력 저장 실패 시 회원 대학/인증/신청 상태/사진 삭제까지 모두 롤백한다.
  이 함수는 다른 트랜잭션 안에서 호출하지 않는다.
  시작 시/약 1분마다/API 접근 시 같은 함수로 정리한다. 정리 실패한 API는 503이다.

[10] DB 테이블과 동시성

  universities: 학교 ID/이름, kind, regions_json, aliases_json, campuses_json, source_date.
  members: 회원 ID/닉네임/대학, salt/password_hash/iterations, university_verified_at.
  sessions: token_hash/member_id/expires_at/created_at.
  runs: member_id/대학/재전송 key/해시/기간/정수 거리/속도/flags/gps_json/policy_version.
  auth_limits: IP별 인증 시도 제한.
  university_verifications: 신청 상태/문서 종류/사진 BLOB/MIME/해시/보관·처리 시각/사유.
  verification_audit: 신청별 처리 이벤트. 사진과 원본 GPS는 이력 API에 포함하지 않는다.

  cr_db_open(): 외래 키 ON, synchronous FULL, secure_delete ON, busy timeout 5초.
  cr_db_init(): WAL, 스키마 버전 검사, v1 -> v2 업그레이드, 목록 시드, 만료 정리.
  요청마다 연결을 따로 쓰고, 여러 값을 함께 바꾸는 작업은 BEGIN IMMEDIATE로 묶는다.
  사용자 입력으로 SQL 문자열을 조립하지 않고 bind를 사용한다.
  중복 key/GPS, pending 1건은 애플리케이션 검사와 DB UNIQUE 제약을 함께 사용한다.
  쓰기 잠금을 가진 상태로 사진 업로드 전체나 긴 GPS 분석을 하지 않도록 순서를 유지한다.

  새 인덱스:
    verification_audit_request(request_id,id): 신청별 이력 조회.
    verification_pending_expiry(expires_at) WHERE status='pending': 만료 대상 탐색.
  테이블 형태 변경 없이 인덱스만 보완하므로 이번 수정의 user_version은 2를 유지한다.
  컬럼/테이블을 바꿀 때는 새 버전의 원자적 마이그레이션과 기존 DB 테스트가 필요하다.
  본인 기록과 GPS JSON은 공개 랭킹/학교 성적 응답에 넣지 않는다.

[11] API 빠른 찾기

공개:
  GET  /health
  GET  /api/universities?q=...&region=...&kind=...
  POST /api/auth/register    {nickname,password,university_id}
  POST /api/auth/login       {nickname,password}
  GET  /api/rankings?from=...&to=...&limit=100&offset=0
  GET  /api/universities/{id}/stats?from=...&to=...
회원 (Authorization: Bearer <회원 토큰>):
  POST /api/auth/logout      {}
  GET/PATCH /api/me          PATCH {nickname?,university_id?}
  POST /api/runs             {key,points:[{timestamp,latitude,longitude},...]}
  GET  /api/me/runs?limit=50&offset=0
  GET  /api/me/runs/{id}     본인만 원본 좌표 포함
  GET  /api/me/stats?from=...&to=...
  POST /api/me/university-verifications              바이너리 사진
  GET  /api/me/university-verifications?limit=20&offset=0
  GET  /api/me/university-verifications/{id}
  GET  /api/me/university-verifications/{id}/image
  POST /api/me/university-verifications/{id}/cancel   {}
관리자 (Authorization: Bearer <관리자 토큰>):
  POST /api/universities     {id,name}
  GET  /api/admin/university-verifications?status=pending&limit=100&offset=0
  GET  /api/admin/university-verifications/{id}
  GET  /api/admin/university-verifications/{id}/image
  GET  /api/admin/university-verifications/{id}/audit?limit=50&offset=0
  POST /api/admin/university-verifications/{id}/decision {decision,reviewer,reason}
  POST /api/admin/university-verifications/{id}/revoke   {reviewer,reason}

  공통 offset: 0~1000000.
  limit 상한: 순위 500, 본인 러닝 200, 신청/처리 이력 100.
  배열 길이가 limit보다 작으면 마지막 페이지다. 데이터 변경 시 offset 페이지가 이동할 수 있다.
  오류는 보통 {"error":"오류코드"}. 성공 status 하나만 가정하지 않는다.
  400 입력 오류, 401 재로그인, 403 관리자/Origin, 404 없음/타인 소유,
  409 중복/이미 처리/대학 변경 제한, 410 사진 삭제, 429 횟수 제한, 500/503 서버/DB 오류.
  사진은 JSON 파싱하지 않는다. 204 logout 응답도 JSON이 없다.

[13] 실행, 설정, 백업, 검증

Windows (저장소 루트에서):
  cd backend
  .\build.ps1 -Test
  .\start-server.ps1
  별도 터미널: python -m http.server 5173 --bind 127.0.0.1 --directory examples
  검토 화면: http://localhost:5173/verification-admin.html

환경 변수:
  CR_ADMIN_TOKEN: 32~256 ASCII 문자. start-server.ps1은 로컬 토큰 파일 생성/재사용.
  CR_ALLOWED_ORIGIN: 기본 http://localhost:5173. 실제 프런트엔드 Origin 하나와 정확히 맞춘다.
    http(s)://호스트[:포트]만 받는다. 경로/끝 슬래시/사용자 정보는 넣지 않는다.
  Listen: IPv4:포트 형식이며 포트는 1~65535. 포트 번호만 넣으면 실행을 거부한다.
  CR_SEED_UNIVERSITIES: 기본 내장 목록 등록, 0이면 시드 비활성화(주로 테스트).
  기본 DB는 start-server.ps1 기준 backend/data/campus.sqlite3.
  DB/토큰/서류/백업 파일은 Git에 올리지 않는다. 개발자마다 로컬 DB를 만든다.

CMake:
  cmake -S backend -B backend/build-cmake -DCMAKE_BUILD_TYPE=Debug
  cmake --build backend/build-cmake --config Debug
  ctest --test-dir backend/build-cmake -C Debug --output-on-failure
  Windows MSVC 한글 경로 디버그 빌드 문제는 README 참고. 이 경로는 build.ps1 사용이 편하다.
  Linux는 OpenSSL 개발 헤더가 필요하다. CI는 Windows/Linux로 설정되어 있다.

백업:
  python tools/backup.py data/campus.sqlite3 backups/new-backup.sqlite3
  기존 대상은 덮어쓰지 않는다. 커밋된 WAL까지 포함한 일관된 사본을 만든다.
  인증 사진을 사본에서 제거하고, 사본의 pending은 재제출이 필요한 cancelled가 된다.
  로그인 세션은 사본에서 모두 제거하므로 복원 후에는 재로그인한다. 운영 DB는 유지한다.
  보호된 임시 디렉터리에서 정리/VACUUM/무결성 검사 후 하드링크로 최종 파일을 공개한다.
  정리 실패/공개 실패 때 최종 백업이 남지 않는지 테스트한다. 기존 파일은 경합 때도 보존한다.
  NTFS/ext4 등 하드링크 지원 저장소가 필요하다. GPS/회원은 남으므로 사본 접근도 제한한다.
  복원 절차와 WAL/SHM 취급은 README의 백업 절을 따른다.

검증 묶음:
  C 분석/등록/TSV 테스트 + CLI 5개 + HTTP 46개 + 백업 7개 + 관리자 화면 11개 + 회원 클라이언트 5개.

  이번 환경에서 Linux/Docker 배포 자체와 실제 휴대폰 GPS 수집은 검증하지 않았다.
  운영 도메인/HTTPS/방화벽/독립 운영자 계정/비밀번호 복구 이메일은 별도 환경 연동 대상이다.

[15] 보안 점검 후 유지할 구현 규칙

  상세 재현/수정/의존성 검토: backend/SECURITY_REVIEW_KO.txt.
  strict_json_input()으로 JSON 숫자/이스케이프/UTF-8/깊이/토큰 수를 검사한 뒤 cJSON에 전달한다.
  JSON 토큰 예산을 바꾸면 정상 GPS 20,000점 테스트를 반드시 통과시킨다.
  쿼리는 퍼센트 디코딩 뒤 NUL/제어 문자/UTF-8까지 검사한다. 숫자 접두사만 취하지 않는다.
  API 경로는 decode_url=no이며 퍼센트 인코딩을 거부한다. 검색 값은 기존처럼 URL 인코딩한다.
  헤더의 중복/Content-Length 문법/Transfer-Encoding 거부는 본문 처리보다 먼저 한다.
  보호된 POST/PATCH/DELETE는 본문을 읽기 전에 인증하고 라우터에서도 다시 확인한다.
  cr_db_init()은 BEGIN IMMEDIATE 안에서 버전을 읽고 스키마 변경을 한 트랜잭션에 처리한다.
  Linux 신규 DB/WAL은 umask 077. 기존 파일 권한과 Windows ACL은 배포 환경에서 설정한다.
  .dockerignore의 DB/토큰/.env/키 파일 제외 규칙을 유지한다.
  backup.py는 세션 삭제와 사진 제거에 실패한 사본을 최종 파일로 공개하면 안 된다.

  PATCH /api/me/password: {current_password,new_password}. 새 salt/해시로 변경한다.
    모든 기존 세션을 폐기하고 새 token/expires_at을 포함한 프로필을 반환한다.
    클라이언트는 반환된 token으로 교체한다. 세션 생성 실패까지 포함해 전체 롤백한다.
  POST /api/auth/logout-all: {}. 본인 모든 세션 폐기 후 204. 비밀번호는 유지한다.
  비밀번호 재확인 실패도 IP별 60초/30회 인증 제한에 포함된다.
  account_change(): deleting 인자로 탈퇴/비밀번호 변경 분기. 회원 ID를 본문에서 받지 않는다.
  CrCredentials: salt[16], hash[32], iterations. 쓰기 전후 자격 증명 비교용 스냅샷이다.
  cr_begin_member_write(): BEGIN IMMEDIATE 후 세션 재확인. 0=성공, 그 외 HTTP 오류.
    계정/프로필/러닝/사진 제출/회원 취소는 이 함수를 사용한다.
    실패 반환 때 트랜잭션은 남지 않는다. 성공 뒤 호출자가 COMMIT/ROLLBACK을 책임진다.
  로그인은 비밀번호 검증 뒤 쓰기 잠금 안에서 닉네임/자격 증명을 다시 확인한다.
  CivetWeb 자동 CORS preflight를 끄고 앱에서 Origin을 검사한다. DELETE도 Allow-Methods에 포함한다.
  verification_member/verification_audit_member 인덱스로 본인 이력/탈퇴 삭제를 지원한다.
  프런트엔드 예제: api.deleteAccount(), changePassword(), logoutAll().
  회원 전용 가입/설정 화면과 이메일 비밀번호 분실 복구는 이 백엔드/API 예제에 포함되지 않는다.
